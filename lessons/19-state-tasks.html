状态 · 任务 · 规划State, Tasks & Planning

AgentState 保存一个 agent 的可持久化状态（如记忆、权限上下文）；Task / TaskContext 描述「正在做的任务」及其上下文。

AgentState holds an agent's persistable state (e.g. memory, permission context); Task / TaskContext describe the task in progress and its context.

🧩 生活类比🧩 Analogy
像游戏的存档：AgentState 是存档文件，下次读档即可从原处继续；Task 则像「当前任务清单」。
Like a game save file: AgentState is the save you reload to continue where you left off, while Task is the "current quest log".

把状态交给 Agent

Handing state to the Agent

在服务化场景（第 23 课），每个会话有自己的状态，由存储后端持久化，从而实现「多会话隔离」与「断点续聊」。TaskContext 是 AgentState 里专门存放任务清单的那部分（即下文规划工具读写的 tasks_context）。

In the service setting (lesson 23) each session has its own state, persisted by the storage backend — enabling "multi-session isolation" and "resume a conversation". TaskContext is the part of AgentState that holds the task list (the tasks_context the planning tools below read and write).

任务规划工具

Task-planning tools

前面讲的是被动的数据（Task / TaskContext）。AgentScope 还提供一组主动的规划工具，让 agent 自己把复杂工作拆成一份可追踪、可更新的计划——这正是 README 里「Task planning」那张动图。在 Agent Service（第 23 课）中，这些工具会被自动加入每个会话的工具箱。

Above we covered the passive data (Task / TaskContext). AgentScope also ships active planning tools that let the agent break complex work into a tracked, updatable plan — this is the README's "Task planning" gif. In the Agent Service (lesson 23) these tools are auto-added to every session's toolkit.

✅ 关键要点✅ Key takeaways
  • AgentState 是 agent 的可持久化状态（记忆、权限上下文等）。AgentState is the agent's persistable state (memory, permission context, …).
  • 不传 state 时 Agent 会自动新建一个。If no state is passed, the Agent creates one.
  • 持久化状态是多会话隔离与续聊的基础。Persisted state underpins multi-session isolation and conversation resume.
  • 规划工具（TaskCreate/TaskUpdate 等）让 agent 自己拆解并追踪计划。Planning tools (TaskCreate/TaskUpdate, …) let the agent break down and track its own plan.
