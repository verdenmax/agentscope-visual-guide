写自己的中间件Custom Middleware

写一个中间件，就是继承 MiddlewareBase 并实现你关心的钩子。每个钩子拿到 agent、本阶段的 input_kwargs 和一个 next_handler——在调用它前后插入你的逻辑。

Writing middleware means subclassing MiddlewareBase and implementing the hooks you care about. Each hook receives the agent, this stage's input_kwargs, and a next_handler — insert your logic before/after calling it.

🧩 生活类比🧩 Analogy
像洋葱的一层：请求向内穿过你这层（你可以记录/改写），到达核心后结果再向外穿回来（你可以再处理一次）。
Like one layer of an onion: the request passes inward through your layer (you can log/rewrite), reaches the core, and the result passes back outward through you (you can post-process).

更多钩子：两种模式

More hooks: two patterns

并非所有钩子都是「洋葱」式。on_model_call / on_reply 等是洋葱模式（拿到 next_handler，前后包裹）；而 on_system_prompt 是转换器模式：直接拿到当前系统提示、返回改写后的版本，多个中间件依次串联。

Not every hook is an "onion". on_model_call / on_reply etc. are the onion pattern (you get next_handler and wrap around it); on_system_prompt is a transformer pattern: you receive the current system prompt and return a rewritten one, chained across middlewares.

📌 注意📌 Note
两个易错点：① 洋葱钩子里必须 await next_handler(**input_kwargs) 才会进入下一层，忘了就拿到一个未执行的协程；② 只需实现你关心的钩子，其余保持默认即可——框架用 is_implemented 判断某钩子是否启用。
Two gotchas: (1) in an onion hook you must await next_handler(**input_kwargs) to reach the next layer — forgetting it yields an un-executed coroutine; (2) implement only the hooks you care about and leave the rest as defaults — the framework uses is_implemented to decide whether a hook is active.

🧠 小测验🧠 Quiz

在自定义中间件的钩子里，如何正确地把控制传给下一层？Inside a custom middleware hook, how do you correctly pass control to the next layer?
  1. 调用并 await：response = await next_handler(**input_kwargs)，再返回结果Call and await it: response = await next_handler(**input_kwargs), then return the result
  2. 调用 next_handler(**input_kwargs) 但不加 awaitCall next_handler(**input_kwargs) but without await
  3. 直接 return None，框架会自动继续往下执行Just return None; the framework continues down the chain automatically
答案与解析Answer & explanation
调用并 await：response = await next_handler(**input_kwargs)，再返回结果Call and await it: response = await next_handler(**input_kwargs), then return the result
钩子是 async 的，必须 await next_handler(...) 才会真正进入下一层；忘记 await 只会拿到一个未执行的协程，而 return None 会中断洋葱链、丢掉下游结果。
Hooks are async, so you must await next_handler(...) to actually enter the next layer; forgetting await yields an un-executed coroutine, and return None breaks the onion chain and drops the downstream result.
