权限系统Permission System

当 agent 能执行命令、改文件时，权限系统是安全闸门。PermissionEngine 依据一组 PermissionRule 与当前 PermissionMode，对每次工具调用作出 PermissionDecision。

Once an agent can run commands and edit files, the permission system is the safety gate. The PermissionEngine makes a PermissionDecision for each tool call from a set of PermissionRules and the current PermissionMode.

🧩 生活类比🧩 Analogy
像公司的门禁与审批：有的门随便进（允许），有的要刷卡（按规则），有的必须主管点头（人工确认），紧急演练时可临时全开（bypass）。
Like corporate access control: some doors are open (allow), some need a badge (rule-based), some need a manager's nod (human confirm), and during a drill you can temporarily open everything (bypass).

当裁决为「需确认」时，agent 会发出 REQUIRE_USER_CONFIRM 事件（见第 9 课），暂停并等待人类批准——这就是 README 里「permission control」与 bypass 模式的来源。

When the decision is "needs confirm", the agent emits a REQUIRE_USER_CONFIRM event (lesson 9), pausing for human approval — this is the source of the README's "permission control" and bypass mode.

两种实操：放行或绕过

Two practical paths: confirm or bypass

默认模式（PermissionMode.DEFAULT）下，写文件等操作会暂停等待确认：reply_stream 发出 REQUIRE_USER_CONFIRM 后即结束。要继续，你需要把一个 UserConfirmResultEvent（含 ConfirmResult）回传给 reply_stream；或在受控场景下改用 PermissionMode.BYPASS 一路放行。

In the default mode (PermissionMode.DEFAULT), operations like writing files pause for confirmation: reply_stream emits REQUIRE_USER_CONFIRM and then ends. To continue you feed a UserConfirmResultEvent (carrying a ConfirmResult) back into reply_stream; or, in controlled settings, use PermissionMode.BYPASS to allow everything.

📌 注意📌 Note
其他模式中最实用的是 ACCEPT_EDITS（自动允许工作目录内的读写，适合开发期快速迭代）。
Among the other modes, the practical one is ACCEPT_EDITS (auto-allow reads/writes inside working directories — handy for rapid development).

✅ 关键要点✅ Key takeaways
  • PermissionEngine 对每次工具调用作出放行/拒绝/确认决策。PermissionEngine decides allow/deny/confirm per tool call.
  • 「需确认」通过 REQUIRE_USER_CONFIRM 事件接入人机交互。"Needs confirm" plugs into human-in-the-loop via the REQUIRE_USER_CONFIRM event.
  • bypass 模式可在受控场景下端到端运行不打断。Bypass mode runs end-to-end without interruption in controlled scenarios.

🧠 小测验🧠 Quiz

关于默认权限模式（PermissionMode.DEFAULT），下列哪项正确？Which statement about the default permission mode (PermissionMode.DEFAULT) is correct?
  1. 写文件等敏感操作会暂停并发出 REQUIRE_USER_CONFIRM，把确认结果回传后才继续Sensitive ops like writing files pause and emit REQUIRE_USER_CONFIRM; you feed the confirmation back to continue
  2. 默认就是 BYPASS，所有工具调用都直接放行The default is BYPASS, so every tool call is allowed straight through
  3. 被拦下的工具会直接抛错并终止整个回复A gated tool throws an error and aborts the whole reply
答案与解析Answer & explanation
写文件等敏感操作会暂停并发出 REQUIRE_USER_CONFIRM，把确认结果回传后才继续Sensitive ops like writing files pause and emit REQUIRE_USER_CONFIRM; you feed the confirmation back to continue
默认模式并非 BYPASS：敏感操作会暂停等待人类批准（回传 UserConfirmResultEvent 即可继续），既不会静默放行，也不会崩溃。
The default is not BYPASS: sensitive ops pause for human approval (feed a UserConfirmResultEvent back to resume) — neither silently allowed nor crashing.
