模型调用内部Model-call Internals

模型调用的内部契约：ChatModelBase 定义统一调用，返回一个 ChatResponse——里面是内容块（文本/思考/工具调用）加上 ChatUsage 用量统计。

The model-call contract: ChatModelBase defines a unified call returning a ChatResponse — content blocks (text/thinking/tool calls) plus a ChatUsage usage record.

🧩 生活类比🧩 Analogy
像统一的快递单：不管哪家快递（厂商），回执的格式都一样——里面装了什么（内容块）、花了多少（用量）一目了然。
Like a standard shipping receipt: whatever the carrier (vendor), the receipt format is the same — what's inside (content blocks) and what it cost (usage) are clear at a glance.

Agent 不直接处理各厂商的原始返回，而是依赖 ChatModelBase 把它们归一化成 ChatResponse——这正是「换厂商不改业务代码」的底层保证。（消息 → 厂商请求的反方向，由 Formatter 负责，见第 11 课。）

The Agent never handles raw vendor payloads; it relies on ChatModelBase to normalize them into a ChatResponse — the underlying guarantee behind "swap vendors without touching business code". (The reverse direction, messages → vendor request, is the Formatter's job, lesson 11.)

结构化输出

Structured output

想让模型直接产出符合某个 schema 的结构化数据（而非自由文本）？用 ChatModelBase.generate_structured_output(messages, structured_model=...)，传入一个 Pydantic 模型，返回 StructuredResponse，其 .content 是符合该 schema 的 dict。

Need the model to emit structured data matching a schema instead of free text? Use ChatModelBase.generate_structured_output(messages, structured_model=...) with a Pydantic model; it returns a StructuredResponse whose .content is a dict matching that schema.

✅ 关键要点✅ Key takeaways
  • 调用返回归一化的 ChatResponse（内容块 + 用量）。A call returns a normalized ChatResponse (content blocks + usage).
  • StructuredResponse 支持结构化输出。StructuredResponse supports structured output.
  • 归一化是「厂商无关」的关键。Normalization is the key to vendor independence.
