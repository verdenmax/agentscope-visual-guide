凭证管理Credentials

凭证（Credential）把「密钥」从「模型配置」里分离出来。每个厂商有自己的CredentialBase 子类，CredentialFactory 可按需创建。

Credentials separate "secrets" from "model config". Each vendor has its own CredentialBase subclass, and CredentialFactory can create them on demand.

🧩 生活类比🧩 Analogy
像门禁卡与办公室分开：办公室（模型）的布置是公开的，门禁卡（密钥）单独保管、单独发放，不写死在墙上。
Like keeping the access card separate from the office: the office (model) layout is public, while the card (secret) is held and issued separately — never written on the wall.
⚠️ 重要⚠️ Important
绝不要把 API key 硬编码进源码。从环境变量或安全配置读取，例如 os.environ["DASHSCOPE_API_KEY"]。
Never hardcode an API key in source. Read it from an environment variable or a secret store, e.g. os.environ["DASHSCOPE_API_KEY"].

其他厂商类似：OpenAICredential、AnthropicCredential、GeminiCredential 等；CredentialFactory 提供按类型创建的统一入口。

Other vendors are analogous: OpenAICredential, AnthropicCredential, GeminiCredential, …; CredentialFactory offers a unified create-by-type entry point.

🔬 源码对应🔬 Source mapping
credential/_base.pyCredentialBaseCredentialBase
credential/_factory.pyCredentialFactoryCredentialFactory
credential/_dashscope.pyDashScopeCredential 等厂商凭证DashScopeCredential and other vendor credentials
✅ 关键要点✅ Key takeaways
  • 凭证与模型配置解耦，便于轮换与多环境管理。Credentials are decoupled from model config — easy to rotate and manage across environments.
  • 永远从环境变量 / 密钥库读取，不要硬编码。Always read from env vars / a secret store — never hardcode.
  • 每个厂商一个 CredentialBase 子类；工厂可按类型创建。One CredentialBase subclass per vendor; the factory creates them by type.

🧠 小测验🧠 Quiz

把凭证（Credential）从模型配置里分离出来，主要好处是什么？What is the main benefit of separating the credential from the model config?
  1. 这样就能把密钥安全地硬编码进凭证对象里So the key can be safely hardcoded into the credential object
  2. 密钥可独立保管与轮换，同一份模型配置能在多环境复用Secrets can be held and rotated independently, and one model config reused across environments
  3. 凭证会自动帮你选择最便宜的模型The credential auto-selects the cheapest model for you
答案与解析Answer & explanation
密钥可独立保管与轮换，同一份模型配置能在多环境复用Secrets can be held and rotated independently, and one model config reused across environments
解耦让密钥单独保管、便于轮换，并能在多环境复用同一模型配置——但密钥仍应从环境变量 / 密钥库读取，绝不硬编码（写进凭证对象也不行）。
Decoupling lets secrets be held separately, rotated, and reused across environments — but keys should still come from env vars / a secret store and be never hardcoded (not even into the credential object).
