一次 reply 的生命周期Lifecycle of a reply

本课跟随一次 reply_stream 调用，看一条用户消息如何穿过整个框架，最终变成一连串事件和一条助手回复。

This lesson follows one reply_stream call to see how a single user message travels through the whole framework and becomes a stream of events plus an assistant reply.

🧩 生活类比🧩 Analogy
像点一杯手冲咖啡：你下单（UserMsg），咖啡师先想用什么豆（推理），可能去取器具（调用工具），过程里不断报进度（事件），最后端上成品（AssistantMsg）。
Like ordering a pour-over: you place an order (UserMsg), the barista first thinks about which beans (reasoning), may fetch equipment (tool calls), keeps announcing progress (events), and finally serves the cup (AssistantMsg).

数据流：从消息到事件

Data flow: from message to events

1
起步Start
你构造一条 UserMsg(name, content)，用 async for 遍历 agent.reply_stream(msg)；回复开始。You build a UserMsg(name, content) and iterate agent.reply_stream(msg) with async for; the reply begins.
2
推理 Reason推理 Reason
Agent 调用模型，流式产出文本 / 思考，或决定调用工具。The agent calls the model, streaming text / thinking or deciding to call tools.
3
行动 Act行动 Act
若模型请求了工具，Agent 执行它们并把结果观察回上下文；受管控的工具会先暂停等待权限确认（第 16 课）。If the model requested tools, the agent runs them and observes the results back into context; gated tools first pause for permission (lesson 16).
4
循环与收尾Loop & finish
推理 → 行动循环往复，直到模型给出最终答案，回复结束。（事件的细节与命名见第 9 课。）Reason → act repeats until the model gives a final answer and the reply ends. (The events and their names are detailed in lesson 9.)

Consuming the stream

⚠️ 重要⚠️ Important
reply_stream 是 async generator，必须用 async for 消费；如果只想要最终结果，用 agent.reply(...)。
reply_stream is an async generator consumed with async for; if you only want the final result, use agent.reply(...).

✅ 关键要点✅ Key takeaways
  • 一次回复 = 推理 → 行动的循环，全程以事件播报。One reply = a reason → act loop, narrated throughout by events.
  • 事件是成对出现的（START → DELTA* → END），便于 UI 渲染。Events come in pairs (START → DELTA* → END), which makes UI rendering straightforward.
  • 权限确认通过 REQUIRE_USER_CONFIRM 事件融入同一条流。Permission confirmation is woven into the same stream via the REQUIRE_USER_CONFIRM event.

🧠 小测验🧠 Quiz

推理阶段模型请求调用一个工具，接下来会发生什么？During reasoning the model requests a tool call. What happens next?
  1. Agent 执行该工具，把结果观察回上下文，再继续「推理→行动」循环，直到给出最终答案The agent runs the tool, observes the result back into context, and continues the reason→act loop until a final answer
  2. 回复立即结束，工具调用本身就是最终结果The reply ends immediately; the tool call itself is the final result
  3. Agent 跳过该工具，直接用模型的纯文本作答The agent skips the tool and answers with the model's plain text
答案与解析Answer & explanation
Agent 执行该工具，把结果观察回上下文，再继续「推理→行动」循环，直到给出最终答案The agent runs the tool, observes the result back into context, and continues the reason→act loop until a final answer
一次回复是「推理→行动」的循环：工具结果会被观察回上下文，模型据此继续推理、可能再次调用工具，直到产出最终 AssistantMsg 才结束。
A reply is a reason→act loop: tool results are observed back into context, the model reasons further (possibly calling more tools), and only the final AssistantMsg ends it.
