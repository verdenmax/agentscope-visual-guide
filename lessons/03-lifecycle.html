一次 reply 的生命周期Lifecycle of a reply

本课跟随一次 reply_stream 调用，看一条用户消息如何穿过整个框架，最终变成一连串事件和一条助手回复。

This lesson follows one reply_stream call to see how a single user message travels through the whole framework and becomes a stream of events plus an assistant reply.

🧩 生活类比🧩 Analogy
像点一杯手冲咖啡：你下单（UserMsg），咖啡师先想用什么豆（推理），可能去取器具（调用工具），过程里不断报进度（事件），最后端上成品（AssistantMsg）。
Like ordering a pour-over: you place an order (UserMsg), the barista first thinks about which beans (reasoning), may fetch equipment (tool calls), keeps announcing progress (events), and finally serves the cup (AssistantMsg).

数据流：从消息到事件

Data flow: from message to events

1① 起步：你发消息并开始消费事件流① Start: you send a message and begin consuming the stream 点击展开expand

你构造一条 UserMsg(name, content) 并 async for 遍历 agent.reply_stream(msg)。Agent 首先发出 REPLY_START。

You build a UserMsg(name, content) and iterate agent.reply_stream(msg) with async for. The agent first emits REPLY_START.

2② 推理：调用模型，流式产出文本 / 思考 / 工具调用② Reason: call the model, streaming text / thinking / tool-calls 点击展开expand

Agent 发出 MODEL_CALL_START，随后模型流式返回：文本块（TEXT_BLOCK_START/DELTA/END）、思考块（THINKING_BLOCK_*）或工具调用（TOOL_CALL_*），最后 MODEL_CALL_END。

The agent emits MODEL_CALL_START, then the model streams back: text blocks (TEXT_BLOCK_START/DELTA/END), thinking blocks (THINKING_BLOCK_*), or tool calls (TOOL_CALL_*), ending with MODEL_CALL_END.

3③ 行动：执行工具（可能需要权限确认）③ Act: execute tools (possibly needing permission) 点击展开expand

若模型请求了工具，Agent 执行它们并产出 TOOL_RESULT_START → TOOL_RESULT_TEXT_DELTA / TOOL_RESULT_DATA_DELTA → TOOL_RESULT_END。若该工具受权限管控，会先发出 REQUIRE_USER_CONFIRM 等待批准。

If the model requested tools, the agent runs them and emits TOOL_RESULT_START → TOOL_RESULT_TEXT_DELTA / TOOL_RESULT_DATA_DELTA → TOOL_RESULT_END. If a tool is permission-gated, it first emits REQUIRE_USER_CONFIRM and waits for approval.

4④ 循环与收尾④ Loop and finish 点击展开expand

推理 → 行动会循环进行，直到模型给出最终答案，Agent 发出 REPLY_END（仅标志本次回复结束，携带 reply_id，不携带最终消息）；若超过最大轮数则发出 EXCEED_MAX_ITERS。最终的 AssistantMsg 通过 agent.reply(...) 获取，或由流式文本块自行累积。

Reason → act repeats until the model produces a final answer and the agent emits REPLY_END (which only signals the reply is complete and carries a reply_id — it does not carry the final message); if it exceeds the iteration cap it emits EXCEED_MAX_ITERS. Obtain the final AssistantMsg via agent.reply(...) or by accumulating the streamed text blocks.

消费事件流

Consuming the stream

⚠️ 重要⚠️ Important
reply_stream 是 async generator，必须用 async for 消费；如果只想要最终结果，用 agent.reply(...)。
reply_stream is an async generator consumed with async for; if you only want the final result, use agent.reply(...).

✅ 关键要点✅ Key takeaways
  • 一次回复 = 推理 → 行动的循环，全程以事件播报。One reply = a reason → act loop, narrated throughout by events.
  • 事件是成对出现的（START → DELTA* → END），便于 UI 渲染。Events come in pairs (START → DELTA* → END), which makes UI rendering straightforward.
  • 权限确认通过 REQUIRE_USER_CONFIRM 事件融入同一条流。Permission confirmation is woven into the same stream via the REQUIRE_USER_CONFIRM event.
