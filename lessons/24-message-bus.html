消息总线Message Bus

消息总线（MessageBus）是服务的中枢神经：它把 agent 事件 发布 / 订阅给前端，并提供分布式的注册表与后台任务追踪、跨 worker 取消。

The MessageBus is the service's nervous system: it publishes/subscribes agent events to the frontend and provides a distributed registry plus background-task tracking and cross-worker cancellation.

🧩 生活类比🧩 Analogy
像一个广播电台 + 公告栏：agent 把进展广播出去（publish），前端调台收听（subscribe）；公告栏（registry）记录「谁在跑什么任务」，任何 worker 都能查到并叫停。
Like a radio station + notice board: agents broadcast progress (publish), frontends tune in (subscribe); the notice board (registry) records "who is running what", and any worker can look it up and stop it.

这套原语正是 README 里那些能力的底座：后台任务卸载（长任务转后台、完成后唤醒 agent 继续对话）与跨 worker 取消（一个进程发起取消，另一个正在执行的进程能收到并停下）。

These primitives underpin the README features: background-task offloading (a long task goes to the background and later wakes the agent to resume) and cross-worker cancellation (one process issues a cancel and another, mid-execution, receives it and stops).

📌 注意📌 Note
目前只提供 RedisMessageBus 这一实现（面向多进程 / 分布式部署）。MessageBus 是统一接口，未来可据此接入更轻量（本地 / 单进程）的实现。
Only the RedisMessageBus implementation ships today (for multi-process / distributed deployments). MessageBus is the uniform interface, designed so lighter (local / single-process) buses can be added later.

✅ 关键要点✅ Key takeaways
  • 消息总线 = 发布/订阅 + 注册表 + 后台任务/取消。The bus = pub/sub + registry + background tasks/cancel.
  • 它支撑后台任务卸载与跨 worker 取消等分布式能力。It powers distributed features like background-task offloading and cross-worker cancel.
  • 目前仅 RedisMessageBus 一种实现；接口统一，未来可扩展。Only RedisMessageBus ships today; the interface is uniform and extensible.

🧠 小测验🧠 Quiz

除了发布 / 订阅事件，消息总线还承担什么职责？Beyond publishing / subscribing events, what else does the message bus do?
  1. 分布式注册表 + 后台任务追踪 + 跨 worker 取消A distributed registry + background-task tracking + cross-worker cancellation
  2. 它只负责事件的发布与订阅，没有其他职责Nothing else — it only publishes and subscribes events
  3. 持久化会话状态与记忆，取代 storage 后端Persisting session state and memory, replacing the storage backend
答案与解析Answer & explanation
分布式注册表 + 后台任务追踪 + 跨 worker 取消A distributed registry + background-task tracking + cross-worker cancellation
registry_* 与 bg_task_* 原语让总线支撑后台任务卸载与跨 worker 取消等分布式能力；持久化会话状态是 storage 后端（第23课）的职责，并非消息总线。
The registry_* and bg_task_* primitives let the bus power background-task offloading and cross-worker cancellation; persisting session state is the storage backend's job (lesson 23), not the message bus's.
