嵌入与检索Embeddings

嵌入（Embedding）把文本变成向量，是检索 / RAG 的基础。EmbeddingModelBase 统一各厂商嵌入模型；EmbeddingCacheBase / FileEmbeddingCache 提供缓存以省钱省时。

Embeddings turn text into vectors — the basis for retrieval / RAG. EmbeddingModelBase unifies vendor embedding models; EmbeddingCacheBase / FileEmbeddingCache add caching to save time and money.

🧩 生活类比🧩 Analogy
像给每段文字一个语义坐标：意思相近的句子坐标也相近，于是「找相似」就变成「找最近的点」。
Like giving each piece of text a semantic coordinate: similar sentences land near each other, so "find similar" becomes "find the nearest point".

调用嵌入模型

Calling an embedding model

拿到向量后，配合向量库（检索最近邻）即可实现 RAG：把相关文档喂回模型上下文。AgentScope 提供嵌入与缓存这块基石；向量库的选择留给你的应用。

With vectors in hand, pair them with a vector store (nearest-neighbor search) to do RAG: feed relevant documents back into the model's context. AgentScope provides the embedding + caching foundation; the vector store choice is left to your application.

从嵌入到 RAG

From embeddings to RAG

检索增强生成（RAG）的典型链路如下。AgentScope 负责其中的嵌入与缓存这块基石，而向量库（存向量、做最近邻检索）由你的应用自选（如 FAISS / Qdrant / pgvector）。

A typical retrieval-augmented-generation (RAG) pipeline looks like this. AgentScope provides the embedding + caching foundation; the vector store (holding vectors and doing nearest-neighbor search) is your application's choice (e.g. FAISS / Qdrant / pgvector).

文档 → 切块 → 嵌入(AgentScope) → 存入向量库(你选) →
    查询时：问题嵌入 → 最近邻检索 → 把相关片段拼进上下文 → 交给 Agent

Document -> chunk -> embed (AgentScope) -> vector store (yours) ->
    at query time: embed the question -> nearest-neighbor search ->
    stuff the relevant chunks into context -> hand to the Agent

📌 注意📌 Note
嵌入调用通常是批量且重复的（同一批文档反复嵌入）。FileEmbeddingCache 把结果缓存到磁盘，命中即跳过 API 调用——既省钱又提速。缓存基类是 EmbeddingCacheBase，可自定义后端。
Embedding calls are often batched and repetitive (re-embedding the same documents). FileEmbeddingCache caches results to disk and skips the API call on a hit — saving money and time. The base is EmbeddingCacheBase, so you can plug in your own backend.
